# 철스크랩 수불현황 대시보드 프로젝트

> 사내 발표용 | 2026-04-14

---

## 1. 프로젝트 개요

### 배경 및 문제 정의

포항소·광양소 두 사업소에서 발생하는 철스크랩의 입고·사용·재고(수불) 데이터는 Excel 파일로 분산 관리되고 있었습니다. 이로 인해 다음과 같은 문제가 반복되었습니다.

- 현황 파악을 위해 매번 Excel 수작업 집계 필요
- 계획 대비 실적 비교, 공급사·구분별 분석에 시간 소요
- 지역별 입고 흐름이나 가격정책 신호를 즉각적으로 파악하기 어려움

### 프로젝트 목적

- **Excel 업로드만으로** 수불 현황을 즉시 시각화
- 계획 대비 실적, 공급사별·구분별·지역별 다각도 분석 자동화
- 구분별(유통/MOU/전용야드) 입고량 변화율을 통한 **가격정책 신호 자동 감지**
- 철강 전문 매체 기사 자동 크롤링을 통한 **구매가격 모니터링** 기능 구현
- AI 챗봇 기반 데이터 질의 기능 프로토타입 구현 (향후 보완 과제)

## 2. 적용 기술 스택 & 학습 기법

본 프로젝트는 수업에서 학습한 기법들을 실제 업무 데이터에 적용하는 것을 목표로 설계되었습니다.

### 2-1. 하이브리드 RAG (Retrieval-Augmented Generation)

| 기법 | 적용 내용 |
|------|----------|
| **BM25** (Sparse 검색) | 키워드 기반 수불 청크 검색 |
| **TF-IDF char n-gram** (Dense-like 검색) | 형태 기반 유사 청크 검색 |
| **RRF (Reciprocal Rank Fusion)** | 두 검색 결과 리랭킹으로 정확도 향상 |
| 동의어 확장 | 재고/입고/사용 도메인 용어 질의 확장 |

수불 데이터를 자연어 청크로 변환(전체 요약, 사소별, 품목별, 월별, 공급사별 등)하고, 하이브리드 서치로 관련 청크를 검색해 GPT에 주입합니다.

### 2-2. LangGraph 조건부 분기

```
질문 입력
  → Router Node (LLM이 질문 유형 분류)
      ├─ [rag]      → RAG Node: 청크 검색 → GPT 답변
      └─ [analysis] → Analysis Node: pandas 코드 생성 → safe exec → 결과 요약
```

- `LangGraph StateGraph` + `add_messages`로 대화 상태 관리
- 단순 조회(재고 현황, 공급사 순위 등) → RAG 경로
- 집계·비율·추이 분석 → 분석 에이전트 경로 자동 라우팅

### 2-3. pandas 코드 생성 에이전트

LLM이 사용자 질문에 맞는 pandas 코드를 생성하고, 제한된 실행 환경(`safe exec`)에서 직접 수행합니다.

- 허용 import: `pandas`, `numpy`만
- 금지 패턴: `import os`, `open()`, `eval()`, `__` 등 위험 패턴 차단
- 결과(`result` 변수)를 다시 LLM이 자연어로 정리

### 2-4. 데이터 파이프라인

- **pandas** 기반 Excel 다중 시트 로드 및 표준화
- `@st.cache_data` / `@st.cache_resource`로 세션 내 캐시 관리
- 구분 분류 우선순위 로직(`classify_gubun_series`)으로 공급사별 자동 분류

### 2-5. 웹 크롤러 (구매가격 모니터링)

철강 전문 매체(스틸데일리, 스크랩워치)의 가격 기사를 자동 수집합니다.

- **requests + BeautifulSoup**: 기사 목록 및 본문 크롤링
- **정규식 파싱**: 제목·본문에서 제강사·품종·방향(인상/인하/보합)·변동폭 자동 추출
- **회사명 정규화**: 패턴 매칭으로 표기 변형 통일 (예: "포항제철소", "POSCO 포항" → "포스코(포항)")
- **APScheduler**: 하루 2회(01:00, 13:00) 자동 크롤링, 수동 즉시 갱신 버튼 병행
- **CSV 기반 저장**: `prices.csv`(확정 데이터), `pending_review.csv`(검토 대기) 이중 관리
- **스크랩워치 검토 워크플로**: 신뢰도가 낮은 기사는 담당자 승인 후 반영

### 2-6. 시각화

- **Plotly**: 월간 추이 막대 차트, 공급사별 입고량, 기간 비교 차트, 제강사별 누적 가격 변동 추이
- **folium + branca**: 한국 17개 시도 Choropleth 지도 (GeoJSON 기반)
- **Streamlit**: 멀티탭, 필터, 파일 업로더, HTML 삽입 인터페이스

## 3. 시스템 아키텍처 & 데이터 흐름

### 전체 파이프라인

```
[사용자]
  Excel 업로드 (수불 데이터, 기준정보)
        │
        ▼
[loader.py]  load_workbooks()
  - 입고 / 사용 / 예상입고량 / 예상사용량 / 기초재고 시트 로드
  - 공급사 구분 분류기 빌드 (build_gubun_classifier)
        │
        ▼
[transform.py]  standardize_movement_df / standardize_expected_df
  - 날짜 기준: 입하일시 - 7시간 (당일 07:00 ~ 익일 06:59)
  - 사소구분 매핑 (SITE_MAP: 광양/광양소 → 광양소)
  - 등급대분류 매핑, 지역 병합
        │
        ▼
[metrics.py]  bucket_metrics() → daily_recv_use_inv()
  - 일별 입고/사용/재고 집계 + is_actual 컬럼 생성
  - 기초재고 기반 누적 재고 계산
        │
        ├──────────────────────────────────────────┐
        ▼                                          ▼
[supplier.py]                              [dashboard/app.py]
  build_supplier_summary()                  수불현황 탭 렌더링
  공급사별 입고량 집계                              │
                                            ▼
                                     [report/exporter.py]
                                      Excel 보고서 출력

[구매가격 모니터링 — 별도 파이프라인]

APScheduler (01:00 / 13:00 자동) 또는 수동 갱신 버튼
        │
        ▼
[price_monitor/crawler.py]  crawl_all()
  - 스틸데일리 / 스크랩워치 기사 크롤링
  - 제강사·품종·방향·변동폭 파싱
  - 스틸데일리 → 확정 레코드 / 스크랩워치 → 검토 대기 레코드
        │
        ▼
[price_monitor/storage.py]
  - prices.csv: 확정 가격 데이터
  - pending_review.csv: 담당자 검토 대기 데이터
        │
        ▼
[dashboard/app.py]  구매가격 모니터링 탭 렌더링
  - 필터 결과 / 전체 데이터 / 가격 추이 차트
```

### 모듈별 역할

| 모듈 | 역할 |
|------|------|
| `pipeline/loader.py` | Excel 로드, 구분 분류기 생성 |
| `pipeline/transform.py` | 날짜 보정, 사소/등급/지역 매핑 표준화 |
| `pipeline/metrics.py` | 일별 입고·사용·재고 집계 |
| `pipeline/supplier.py` | 공급사별 입고량 집계 |

| `pipeline/graph.py` | LangGraph 챗봇 플로우 (향후 보완 과제) |
| `pipeline/gubun_signal.py` | 구분별 가격정책 신호 감지 로직 |
| `price_monitor/crawler.py` | 스틸데일리·스크랩워치 기사 크롤링 및 파싱 |
| `price_monitor/storage.py` | 가격 데이터 CSV 저장·조회·검토 워크플로 관리 |
| `dashboard/app.py` | Streamlit 메인 앱, 수불현황·구매가격 모니터링 2탭 렌더링 |
| `dashboard/charts.py` | Plotly 차트 함수 모음 |
| `report/exporter.py` | Excel 보고서 출력 |

## 4. 주요 기능 상세

### 4-1. 월간 추이

**탭 A — 단일 월 심층 분석**

- 선택 월의 일별 입고·사용·재고 추이 막대 차트
- 실적 vs 계획 KPI 박스 (달성률 표시)

**탭 B — 멀티 월 비교**

- 여러 달의 입고/사용량을 나란히 놓고 비교하는 그룹 막대 차트
- 월간 증감 패턴 한눈에 파악

### 4-2. 입고 상세 분석

- **필터**: 기간 / 사소구분 / 구분(유통·MOU·전용야드) / 공급사 / 품목 / 등급
- **단일 기간 모드**: 선택 기간의 공급사별·등급별 입고 내역
- **A vs B 기간 비교 모드**: 두 기간의 입고량 차이를 나란히 시각화

### 4-3. 구분별 가격정책 신호 감지

구분별(유통/MOU/전용야드) 입고량 변화율을 자동 계산합니다.

- 전월 대비 / 전주 대비 입고량 증감률 산출
- 급격한 변화 감지 시 정책 신호로 표시
- 철스크랩 시장 가격 움직임의 선행 지표로 활용

### 4-4. 지역별 입고 현황 지도

- 한국 17개 시도 GeoJSON 기반 Choropleth 지도
- 색상: 연한 파랑(`#dbeafe`) → 진한 파랑(`#1e3a8a`), 입고량 비례
- 지역 매핑: 경인(서울/인천/경기), 경남(부산/울산/경상남도) 등 권역별 집계

### 4-5. 구매가격 모니터링

철강 전문 매체 기사를 자동 수집해 제강사별 스크랩 구매가격 동향을 추적합니다.

**크롤링 대상**
- 스틸데일리: 기사 자동 수집 → 확정 데이터로 즉시 저장
- 스크랩워치: 수집 후 담당자 검토 대기 → 승인 시 반영 (신뢰도 검증 워크플로)

**자동화**
- APScheduler로 하루 2회(01:00, 13:00) 자동 크롤링
- "지금 갱신" 버튼으로 수동 즉시 실행 가능

**파싱 항목**

| 항목 | 내용 |
|------|------|
| 제강사 | 포스코(포항/광양), 현대제철(인천/당진/포항), 동국제강(인천/포항), 세아 등 |
| 품종 | 생철, 중량, 경량, 선반 |
| 방향 | 인상 / 인하 / 보합 |
| 변동폭 | 원/톤 단위 (원/kg 입력 시 자동 변환) |

**화면 구성 (3개 서브탭)**
- 필터 결과: 구분·신문사·제강사·품종·기간 필터 적용 결과
- 전체 데이터: 국내/수입 전체 가격 이력 + 스크랩워치 검토 대기 관리
- 가격 추이 차트: 제강사별 누적 가격 변동 추이 시각화

**수동 입력**: 크롤링 외 별도 입수 정보를 직접 등록 가능

### 4-6. AI 챗봇 (향후 보완 과제)

LangGraph 기반 RAG + 분석 에이전트 프로토타입을 구현했으나, 현재는 기능 검증 단계입니다. 안정화 및 고도화는 중장기 과제로 진행합니다.

## 6. 단기 적용 계획 (1~3개월)

### 6-1. 메일 발송 기능 정상화

**현황**: Gmail SMTP SSL(포트 465/587)이 법인 방화벽에 의해 차단되어 발송 불가

**해결 방향**:
- IT 부서를 통해 내부 SMTP 서버 정보(호스트, 포트, 인증 방식) 확인
- `_send_gmail()` 함수를 내부 SMTP 연동 방식으로 교체
- 발송 성공/실패 로그 추가

### 6-2. Streamlit API 호환성 교체

**현황**: `use_container_width` 파라미터가 2025-12-31 이후 deprecated 예정

**해결 방향**:
- 전체 코드에서 `use_container_width=True` → `width='stretch'`로 일괄 교체
- Streamlit 최신 버전 업그레이드 후 경고 없는 환경 유지

## 7. 중장기 적용 계획 (6개월~1년)

### 7-1. AI 챗봇 고도화

현재 프로토타입 수준의 LangGraph 챗봇을 실무 사용 가능 수준으로 안정화합니다.

- RAG 청크 품질 개선 (더 세밀한 집계 단위, 청크 overlap 전략)
- 벡터 DB(예: FAISS, ChromaDB) 도입으로 대용량 데이터 대응
- 멀티턴 대화 품질 향상 (이전 질문 맥락 유지)
- 답변 신뢰도 지표 표시

### 7-2. 실시간 데이터 연동

- Excel 수동 업로드 방식에서 ERP/데이터베이스 직접 연동으로 전환
- 자동 스케줄 갱신 (일별 데이터 자동 반영)

### 7-3. 알림 기능 확장

- 재고 임계치 도달 시 자동 알림 (메일/메신저)
- 가격정책 신호 감지 시 담당자 자동 통보

### 7-4. 사용자 권한 관리

- 사소별 접근 권한 분리 (포항소 담당자는 포항소 데이터만 조회)
- 관리자/일반 사용자 역할 구분

## 8. 기대 효과

### 정량적 효과

| 항목 | 기대 효과 |
|------|----------|
| 현황 파악 시간 | Excel 수작업 집계 → 업로드 즉시 대시보드 확인 |
| 계획 대비 실적 분석 | 수동 비교 → 자동 KPI 박스·차트 제공 |
| 가격정책 신호 감지 | 담당자 경험에 의존 → 전월/전주 대비 변화율 자동 산출 |
| 구매가격 동향 파악 | 매체 수동 모니터링 → 기사 자동 크롤링 + 필터·차트 제공 |
| 보고서 작성 | Excel 재가공 → 대시보드에서 직접 Excel 보고서 다운로드 |

### 정성적 효과

- **의사결정 속도 향상**: 지역별·공급사별·구분별 현황을 한 화면에서 즉시 파악
- **분석 일관성 확보**: 구분 분류 로직·날짜 기준이 코드로 표준화되어 담당자 간 해석 차이 제거
- **확장 가능한 기반 마련**: 모듈형 파이프라인 구조로 신규 데이터 소스·분석 기능 추가 용이
- **AI 활용 역량 내재화**: 하이브리드 RAG, LangGraph 등 최신 AI 기법을 실무 데이터에 직접 적용한 경험 축적
